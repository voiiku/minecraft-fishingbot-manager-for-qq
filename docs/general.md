# general：通用指令

* 代码：`src/general.rs` + `src/general/*.rs`
* 与本项目其它模块**没有耦合**：不读机器人目录、不碰 screen 会话，
  因此可以单独取用、单独测试。
* 三条指令一律不需要权限（谁都能用）。

## 一、指令一览

| 指令 | 函数 | 是否网络请求 |
| --- | --- | --- |
| `/help` | `help::help()` | 否 |
| `/ping [地址] [端口]` | `ping::ping(host, port)` | 是（MC 服务器握手） |
| `/checkserver` | `checkserver::checkserver()` | 否（读本机资源） |

## 二、`/help`

* 直接返回配置里的 `text.help` 原文（三引号多行字符串），**改文案不用重新编译**。
* **群聊与私聊都能用**（私聊里是少数几条可用指令之一，见 [command-router.md](command-router.md) 第五节）。
* 因此帮助菜单与实际支持的指令可能不同步：改了指令记得同步改配置，
  这一点在配置文件里也写明了。

## 三、`/ping`

* 不带参数时用 `[ping]` 表的默认目标（`default_ping_host` / `default_ping_port`）；
  带参数时以聊天里给的为准（端口解析失败就退回默认逻辑）。
* 走 Minecraft 服务器列表握手（`craftping`），因此拿到的是**游戏层**的响应：在线人数 / 最大人数，
  以及「钓鱼服务器 → 游戏服务器」这一跳的延迟，而不是简单的 TCP 连通性。
* 输出固定三行：`状态: 在线`、`人数: 当前人数/上限`、`延迟: N ms（钓鱼服务器到游戏服务器的延迟）`；连不上/超时/协议解析失败各给一条可读文案。
* 连接超时取 `ping.timeout_ms`（配置校验保证它不为 0，否则永远等不到响应）。
* 地址/端口非法、连不上、超时都会各自给出可读文案，不 panic。

## 四、`/checkserver`

* 报告的是**跑本程序的这台机器**（钓鱼进程所在机器）的资源，不是游戏服务器。
* 数据来自 `sysinfo`：CPU 使用率、内存、磁盘、系统运行时长。
* CPU 使用率取**两次采样**（间隔很短）再计算差值：单次采样拿到的是相对开机以来的平均值，
  会长时间停留在高位、看起来像是满载。
* 输出是固定字段的多行文本，方便直接截图，不依赖日志文件。
